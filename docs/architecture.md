# Архитектура «Touch me»

Краткая карта слоёв для контрибьюторов. Полную картину фазы 1 (аудит
компонентов, соответствие узлам ComfyUI, план интеграции) проект ведёт во
внутренней документации; здесь — то, что нужно для ориентирования в коде.

## Слои (сверху вниз)

1. **Компоненты UI** — `src/components/touchme/`
   - `TouchMeApp` — корневой контейнер: просмотрщик, шапка, нижняя лента и
     три оверлея (настройки, галерея, полноэкранный промпт).
   - `ImageViewer` — жесты: свайп-переключение, двойной тап (зум ×2.2),
     pinch 1–8×, pan, одиночный тап — скрыть/показать интерфейс.
   - `SettingsSheet` + `panels/*` — девять панелей настроек: Модели, LoRA,
     Fooocus-стили, Промпт, Разрешение, KSampler, Режимы, Изображение (img2img),
     Upscale. Состав нижней ленты вычисляется из активных режимов.
   - `GallerySheet` — полноэкранная галерея с переименованием.
2. **Состояние** — `src/store/touchme/` (Zustand), три независимых стора:
   - `useAppStore` — UI-состояние (активные панели, режим переименования).
   - `useGalleryStore` — изображения галереи (сейчас — демо-данные).
   - `useGenerationStore` — режимы обработки и все параметры генерации;
     структура повторяет параметры нод ComfyUI (loaders / loras / ksampler /
     upscale) — при интеграции граф собирается прямо из этого стора.
3. **Источники данных** — `src/lib/touchme/data/sources.ts`
   Единственная точка, откуда UI получает списки: модели — через собственный
   маршрут `/api/models`; Fooocus-стили — из ресурса `fooocus_styles.json`;
   сэмплеры/шедулеры/пресеты — статика. На этапе 2 функции источников
   заменяются на запросы к `/object_info` живого ComfyUI без изменения
   UI-кода.
4. **Серверный маршрут** — `src/app/api/models/route.ts`
   Сканер каталога моделей по стандартным категориям ComfyUI
   (checkpoints/unet/clip/vae/loras/controlnet/upscale_models, рекурсивно).
   Путь задаётся `COMFYUI_MODELS_DIR`, по умолчанию — `<проект>/models`.
   Если маршрут недоступен (статический бандл внутри ComfyUI) или каталог
   пуст, `sources.ts` возвращает встроенный демо-набор имён
   (`demo_models.ts`) — офлайн-фолбэк, а не эмуляция сканера.

## Два режима поставки

- **Веб-приложение** (разработка): Next.js dev/standalone-сервер,
  `/api/models` работает, демо-галерея в `public/`.
- **Кастом-нода ComfyUI** (использование): корневой `__init__.py`
  регистрирует в `PromptServer` маршруты `/touchme` и `/touchme/{tail}`,
  которые отдаляют статический бандл из `web/`. Тот же origin, что и
  ComfyUI, — на этапе 2 не будет ни CORS, ни mixed-content. Пересборка
  бандла: `scripts/build_comfyui_web.sh` (экспорт без `/api/models`;
  панель «Модели» в этом режиме живёт на демо-наборе). Офлайн-проверка
  маршрутов: `scripts/test_web_serve.py`.

## Планируемый слой интеграции (этап 2)

- **ComfyApiClient** — HTTP-клиент (`src/lib/touchme/api/client.ts`):
  `/prompt`, `/queue`, `/interrupt`, `/history`, `/view`, `/upload/image`,
  `/upload/mask`, `/object_info`, `/system_stats`.
- **ComfySocket** — WebSocket `/ws?clientId=…`: прогресс, события выполнения,
  бинарные превью в реальном времени.
- **Реестр workflow-шаблонов** — `workflows/*.json` в API-формате + манифест
  биндингов «узел → вход → поле стора» (см. `workflows/README.md`).
- **GraphBuilder** — чистая функция: (состояние стора, шаблон) → prompt JSON
  для `POST /prompt`. Переключение режимов (t2i / img2img / upscale / inpaint)
  — это патч связей графа, а не флаги узлов.

Принцип: **интерфейс не знает конкретного workflow**. Конкретный граф живёт
в реестре шаблонов и подключается файлом; добавление нового графа не требует
изменений UI-кода.

Контракт с ComfyUI (эндпоинты, WebSocket, форматы, CORS/туннели) —
в [`docs/comfy-api.md`](./comfy-api.md).
